==================== CRUD ======================================================

PATH PARAMETERS:
- are request parameters attached with URL
http://127.0.0.1:8000/books/bookA

QUERY PARAMETERS:
- are request parameters attached after question mark (as name=value pair)
- NOTE: Query parameter are not the part of route identity
        ie. "/book" and "/book/" are two different path, but
            "/book?category=science" and "/book?author=X"  are similar and has to
             be handled in the same function
http://127.0.0.1:8000/books?category=history


- fastAPI looks from top to bottom to match the URL for picking the function to call

Body()
- specify explicitly --the function parameters value must fetched from
    request body not from url path or query parameters


======== Data Validation/Exception/Status code/Request object ==================

for GET -- to validate Path/Query parameter -->
   Path parameter  -> use Path class  (imported from fastapi)
   Query parameter -> use Query class
   NOTE: Apply these classes to the function parameters
for POST -- to validate request body --> use pydantic


PYDANTIC:
- used for data parsing, data validation, data serialization(json <-> py objects)
- data received from POST request is validated using pydantic
  STEPS:
    - model creation -- similar to class object       (by inheriting BaseModel)
    - in this model, add validation on each variables (using Fields)
    - pass this model instead of Body() to parse the request body

- use 'model_config', to populate default values in the 'Example Value' section (in UI)


STATUS CODES:
  1xx - information request
  2xx - success
  3xx - redirection
  4xx - client side error
  5xx - server side issue

SQLite CONFIGURATION STEPS (boilerplate code):

HASHING PASSWORD:
libs required -> passlib, bcrypt==4.0.1

AUTHENTICATING USER (LOGIN):
libs required -> python-multipart (for form submission)
 - use OAuth2PasswordRequestForm from python-multipart as dependency injection
 - this form has default fields setup to get the username and passwd
 - get the username & retrive the User object with similar username
 - using bcrypt verify the passwd with hashed passwd
 - it matches, then return an JWT token (Json Web Token - contain info of user)

JSON WEB TOKEN (JWT)
- secure way to transmit data as JSON objects
- JST are digitall signed, so it's tamper proof
- JST is used for authorization, not as authentication request
- after authentication(login), each request carries JWT to know the server about the user

JWT STRUCTURE:
 - 3 parts data seperated by dots =>  header.payload.signature

  HEADER:
    - contain two fields and header is encoded in Base64
    {
      "algo": "algorithm for signing"
      "typ":  "type of token"
    }

  PAYLOAD:
    - contain data + additonal information, also encoded in Base64

  SIGNATURE:
    - contain signature created with algorithm specified in header
    - hash is generated by
        algorithm(encoded(header) + encoded(payload), SECRET) -> hash

 - website for creating/decrypting JWT tokens manually -> https://www.jwt.io/
 - lib required -> "python-jose[cryptography]"    (For generating JWT token)

HOW JWT TOKEN IS SENT FROM BROWSER?
for get request, the jwt token is sent in request header (like below)

GET /api/posts HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
Accept: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1c2VySWQiOiIxMjM0NSIsImV4cCI6MTc5OTk5OTk5OX0.SignatureHere
Connection: keep-alive

- class from 'OAuth2PasswordBearer' reads the header, check for 'Authorization'
    retrieve the token and inject it into the API end point function
- if in case the token is missing, then it will raise 404 error

=========================== ALEMBIC ============================================
Alembic
- data migration tool, allow to modify database schemes while it has data in it
- ie. it allow to create additional contents in the tables
- to install:  pip install alembic

1. to initialize alembic
    alembic init <foldername>

        alembic.ini - configuration file
           i. update the sqlalchemy.url with the url used in database.py file

        alembic/versions/env.py
           i. import models
           ii. update target_metadata

2. to upgrade(add new col) DB create alembic revision file
    a> need to create a new alembic file also called Alembic Revision
    b> within the file add what kind of changes is needed

    alembic revision -m "create phone number col on user table"
        // this will create a file (alembic revision) to write the upgrade code
        // each these revision (ie db changes) has unique revision id associated with it

3. run upgrade to apply the revision to the database
    alembic upgrade <revision_id>

- similarly to downgrade, create a revision file and update the file
- to apply the revision, run
    alembic downgrade -1     // reverse the last revision applied
